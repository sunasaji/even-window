# トラブルシューティング

[English](troubleshooting.md) | 日本語

まずログを見てください。たいていの問題は、そこに原因が名指しで出ています。

## ログの場所

| 出どころ | 場所 |
| --- | --- |
| 手で起動したサーバ | そのターミナル。行は `[ew]` で始まり、Linux バックエンドは `[x11]` を使います。 |
| systemd ユニットのサーバ | `journalctl --user -u 'even-window@*' -f` |
| `scripts/dev.sh` で起動したサーバ | `.ew-x11/logs/dev-api.log`（と `dev-vite.log`） |
| クライアント | スマホ画面の **log** パネル。**copy** ボタンがあります |
| アプリが落ちたあとのクライアント | あらかじめ `?debug=1` を付けてアプリを読み込んでおきます。クライアントの行が `[ew] CLIENT …` としてサーバのログに転送されます。まとめて送られるので、落ちる直前の数行は欠けることがあります。 |
| 音声認識サービス | `journalctl --user -u speech-cpp -n 50` |

サーバの起動時のバナーは、認証の状態、登録済みの端末数とそのレジストリ、使っている
env ファイル、セッション束縛の状態を報告します。

## 接続とペアリング

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `/api/health` への死活監視が `401` になる | 想定どおりです。このルートは認証が必要で、`401` はリスナとゲートが動いている証拠です。 | `200` と `401` の両方を「生きている」と扱ってください。 |
| ペアリングを承認したのに、すべてのリクエストが `401` になる | `EW_ORIGIN` が、端末がダイヤルする URL と一致していません。署名は宛先を名指ししています。 | `EW_ORIGIN` を端末のアドレスバーの URL（スキーム、ホスト、ポート）と正確に同じにして再起動します。 |
| すべてのリクエストが `401` で、バナーに `NO CLIENT KEYS ENROLLED in …` と出る | サーバが、端末を登録したのとは別の状態ディレクトリを使っています。`scripts/dev.sh` は `.ew-x11/state` を使います。 | ペアリングしたときと同じ方法でサーバを起動するか、サーバと `ew-auth.mjs` で `EW_STATE_DIR` を揃えます。 |
| `ew-auth pair` が `NO FREE SLOT`、または `approve` が `REFUSED` と表示する | 登録数の上限（`EW_MAX_CLIENTS`、既定 1）に達しています。ペアリングし直すと鍵は置き換わらず、追加されます。 | `ew-auth.mjs list` で確認し、置き換える鍵を `revoke <id>` してからペアリングします。拒否された承認待ちの端末は残るので、失効のあとに承認できます。複数の端末を使い続けるなら、`EW_MAX_CLIENTS` を上げて再起動します。 |
| サーバが `REFUSING TO START` で終了する | `EW_MAX_CLIENTS` が許す数より多くの鍵が登録されています。上限を下げても何も失効しません。 | 余分な鍵を失効させる（サーバは不要）か、上限を実際に使う数にします。 |
| `No device paired within the window` | ペアリング窓（2 分、1 台）の期限が切れました。 | もう一度 `pair` を実行します。 |
| スマホが別のサーバへの切り替えの確認を求める | `?server=` つきのリンクが、ペアリング済みの端末を別の API ベースに向けようとしています。 | 自分でアドレスを変えた場合だけ承認してください。 |
| Vite が `Blocked request. This host is not allowed.` と応答する | そのホスト名が Vite の許可リストにありません。 | `EW_ALLOWED_HOSTS=<name> npm run dev`。`*.ts.net` は常に許可されています。 |
| `tailscale serve` 経由で `/api/...` が `404` になる | プロキシのターゲットに `/api` が付いておらず、プレフィックスが取り除かれています。 | `--set-path /api http://127.0.0.1:8787/api` を使います。 |
| プロキシの後ろでホットリロードが効かなくなった | ホットリロードのクライアントが開発用のポートへ接続しようとしています。 | `EW_HMR_HOST` と `EW_HMR_PORT` を設定します。 |
| サーバを再起動したあと、スマホが切断されたままになる | Even App はストリームを開き直さないことがあります。 | アプリを開き直します。 |
| env ファイルの設定が効かない | ファイルが無視された（ほかのユーザが書き込める）、その行が拒否された、または環境変数がすでに設定されていた、のいずれかです。 | バナーの `env file` の行を読みます。ファイルを `chmod 600` にし、`export` と `=` の前後の空白を取り除きます。 |

## グラスに何も映らない

まずスマホを確認してください。プレビューにデスクトップが映っていれば、サーバ側は正常です。

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| プレビューは動いているがレンズが暗く、ボタンの表示が **lens:off** か **lens:case** | ラッチまたはケースのセンサでミラーが一時停止しています。 | **lens** ボタンをタップします。 |
| プレビューは動いているがレンズが暗く、画面の大半が黒い | グラスでは黒は透明です。空のデスクトップや黒いウィンドウは何も映しません。 | 何かを起動するか、`EW_SPAWN` が空でないか確認します。 |
| スマホに `another instance owns the glasses` と表示される | 新しく開いたアプリのコピーがグラスを引き継ぎました。 | もう一方のコピーを閉じるか、こちらをリロードしてグラスを取り戻します。 |
| ログに `glasses link DOWN` と出る | グラスとの Bluetooth リンクが切れています。戻るまで更新は止まります。 | Even App でグラスを接続し直します。ミラーが再開しなければ、アプリを開き直します。 |
| プレビューも黒い、または止まっている | サーバにセッションが無いか、キャプチャが動いていません。 | サーバのログで `[x11]` の行を探し、後述の節を参照します。 |

## ジェスチャと入力

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| スワイプは効くのにダブルタップが効かない、または新しい機能が無いように見える | バージョンのずれです。クライアントは作業ツリーから最新のものが配信されますが、サーバのプロセスは古いままです。 | サーバを再起動します。開いているウィンドウは再起動後も残ります。`ps -o lstart= -p <pid>` を最後に更新した時刻と比べてください。 |
| スワイプが違うキーを送る | 想定していない割り当てが適用されています。 | サーバは `input gesture=up … key=… via=…` をログに出します。`via` が、採用された割り当てです。**app** パネルで編集します。 |
| **Submit** で文字は入力されるが実行されない | submit キーの既定は `off` です。 | **app** パネルで、そのアプリケーションの **submit** を設定します。 |
| Bluetooth キーボードの矢印キーが効かない | iOS の WebView は矢印キーを届けません。 | **keys** パネルを使います。 |
| Bluetooth を切ると Even App が終了する | リンクが切れたあとの Even App の既知の障害です。[status.ja.md](status.ja.md) を参照。 | グラスなしでアプリを使うには、Bluetooth を先に切ってからアプリを起動します。 |

## 音声入力

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 長押ししても何も起きず、**voice** ボタンも無い | 認識サービスが設定されていません。クライアントは、サーバが認識サービスありと報告したときだけ音声入力を提供します。 | `EW_STT_URL` を設定してサーバを再起動します。 |
| 認識が `404` で失敗する | 送っているモデル ID が、認識サービスが提供している ID と違います。 | `EW_STT_MODEL` を `curl -s http://127.0.0.1:8757/v1/models` の結果と比べます。 |
| 認識サービスが初回の起動直後に応答しない | モデルをダウンロードしています。 | 先にシェルから `speech pull <model>` を実行します。 |
| スマホのマイクを使っていて、数秒後に `no audio` になる | Even App にマイクの権限がありません。 | スマホの設定で許可します。 |

## ミラーデスクトップ（Linux バックエンド）

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| ログに `:100` ではなく `127.0.0.1:100` と出る | `/tmp/.X11-unix` に新しいソケットを作れない（WSLg では sticky で書き込み可能なディレクトリになっていない）ため、ネストした X が TCP で待ち受けています。 | 正常です。X のツールを手で実行するときは `DISPLAY=127.0.0.1:100` を使います。 |
| 手で起動したネスト X サーバが `failed to create listener for unix` で終了する | 同じ `/tmp/.X11-unix` の制約です。 | `-listen tcp` を付けて起動し、`127.0.0.1:<n>` に接続します。 |
| 手で起動したアプリケーションが Windows のデスクトップに出る | WSLg では、`WAYLAND_DISPLAY` があると GTK アプリケーションは Wayland を優先します。サーバは自分が起動するものについてはこれを取り除きますが、シェルはそうしません。 | `env -u WAYLAND_DISPLAY GDK_BACKEND=x11 DISPLAY=127.0.0.1:100 <command>` |
| デスクトップに Xephyr のウィンドウが出ない、またはヘッドレスにしたいのに出る | バックエンドはホストのディスプレイに従って決まり、生きているセッションにはそのまま再アタッチします。 | `EW_HOST_DISPLAY`（ヘッドレスなら空）か `EW_BACKEND` を設定し、古い X サーバを pid 指定で終了させ、`.ew-x11/session.json` を削除して再起動します。 |
| `EW_BACKEND=xephyr` でセッションが起動しない | バックエンドを固定すると切り替えは行われず、Xephyr にはホストのディスプレイが必要です。 | `auto` を使うか、ホストのディスプレイを用意します。 |
| ログに `<backend> did not come up on :N` と出る | その行に原因が書かれています。`exited with code …` は X サーバが起動できなかった場合（未インストール、ディスプレイ番号が使用中、ホストのディスプレイがない）。`still running … but accepts no connection` は、起動はしたが unix ソケットも TCP ポートも 5 秒以内に応答しなかった場合で、TCP ポートが `gave no answer at all` ならループバックのパケットが破棄されています。 | X サーバを入れる、ディスプレイ番号を空ける、ホストのディスプレイを用意する。後者の場合は `/tmp/.X11-unix` の権限とローカルのファイアウォールを確認します。 |
| ポートが使用中でサーバが待ち受けできない | 別のインスタンスが動いています。 | `ss -ltnp \| grep 8787` で確認して止めるか、`EW_PORT` を変えます（別のデスクトップを保つなら `EW_X11_DISPLAY` も）。 |
| 起動したプログラムの作業ディレクトリが違う | `EW_SPAWN_CWD` がディレクトリではありません。サーバは警告を出して `$HOME` に切り替えます。 | パスを直します。 |

### Firefox の右端が切れる

Firefox の既定の最小ウィンドウ幅が画面より大きいためです。`scripts/ew-firefox.sh` から
起動してください。[firefox.ja.md](firefox.ja.md) を参照。

### WSL2 で Firefox が起動しない

snap パッケージの Firefox は TCP の X 接続を開けませんが、WSLg で使えるのは TCP の接続
だけです（`cannot open display`）。`.deb` パッケージか公式の tarball から Firefox を
インストールし、`PATH` の先頭にない場合は `EW_FIREFOX_BIN` で指定してください。

## それでも解決しないとき

起動時からのサーバのログ、スマホの **log** パネル、`node scripts/ew-auth.mjs list` の
出力を集め、[status.ja.md](status.ja.md) の既知の制限を確認したうえで、issue として
報告してください。
